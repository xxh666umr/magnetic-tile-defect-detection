# 评价说明

本文记录模型在**验证集 202 张**上的完整评价过程与结果，对应脚本 `val.py`，原始输出见仓库根目录 `val_summary.json`。

## 1. 数据划分

| 划分 | 数量 | 用途 |
|---|---|---|
| 训练集 | 936 | 训练 |
| 验证集 | 202 | 调参 + 本文所有指标 |
| 测试集 | 202 | 保留不动 |

训练与验证严格分开，指标不来自训练时见过的图片。

## 2. 评价口径

两个层次：

1. **检测级**：沿用 ultralytics 的 `model.val()`，`conf=0.25`，输出 Precision / Recall / mAP / 各类别召回率。
2. **工件级**：按"一张工件是否 NG"统计。判定规则与系统一致——存在 `conf >= 0.25` 的缺陷框即 NG，否则 OK。再与标注对比：

   - **漏放**（miss）：真实有缺陷（该图有标注框）却判成 OK —— 质检中最不能接受的错误
   - **误杀**（false kill）：真实无缺陷却判成 NG
   - **判定准确率** = (OK 判对 + NG 判对) / 总数

## 3. 总体结果

| 指标 | 数值 |
|---|---|
| Precision | 0.8840 |
| Recall | 0.8070 |
| F1 | 0.8438 |
| mAP@0.5 | 0.7671 |
| mAP@0.5:0.95 | 0.4913 |
| 工件级判定准确率 | 200/202 = 99.01% |
| 真实 NG 数 | 59 |
| 漏放 | 0 |
| 误杀 | 2 |

## 4. 分类别召回率

| 类别 | 中文 | Recall |
|---|---|---|
| blowhole | 气孔 | 0.9758 |
| break | 崩边 | 0.4375 |
| crack | 裂纹 | 1.0000 |
| fray | 毛边 | 0.8571 |
| uneven | 不平整 | 0.7647 |

## 5. 结果解读

- **工件级漏放为 0**，是这套系统目前最有价值的结论：在 59 张真实缺陷件上，没有一张被误判为 OK。对产线来说，"漏放"的代价远高于"误杀"。
- **mAP@0.5 只有 0.767**，说明定位精度一般，主要拖累来自崩边。
- **崩边召回 0.4375 是明确短板**。可能原因：缺陷区域小、与背景灰度对比弱、训练样本偏少。可尝试的改进：提高 `imgsz`（如 960/1280）、针对小目标做复制粘贴增强（copy-paste）、补充崩边样本、按类别分别调置信度阈值。
- **误杀 2 张**属于可接受范围：宁可多判 NG 让人工复检，也不要放过缺陷件。

## 6. 复现方式

```bash
# 需要先准备好数据集与训练好的权重
python val.py
```

脚本会把汇总结果写入 `val_summary.json`，并在控制台打印全部指标。
